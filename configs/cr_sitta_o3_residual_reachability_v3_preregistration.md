# 先检查机制：已有残差方向的可达性诊断 v3

## 问题与已知边界

v1 在当前 NUDT train8 拟合集上优于背景惩罚 v2，但仍有漏检和背景扩张。
这些现象不证明缺少门控、梯度冲突或表征不足。v1 本身已有输入条件化的局部处理。
本轮只问：假如知道每个位置的正确标签，仅调整 v1 已有残差的强弱，是否足以修复错误？
这先检查候选机制的必要条件，不先实现新模型，不用训练损失或工程通过替代性能证据。

## 数学与数值口径

原 output_0 是冻结的 1×1 仿射头。若新增跨通道共享、逐位置的标量 a，
`h_new = h_o3 + a * (h_v1 - h_o3)`，则理想实数运算下
`z_new = z_o3 + a * (z_v1 - z_o3)`。
拟议 `a=1+tanh(g)` 的开区间 (0,2) 放松成闭区间 [0,2]，给予候选更乐观的能力。
包络端点为 z_o3 与 2*z_v1-z_o3；用实际重放的 float32 logits 转 float64 计算。
这是理想 logit 包络，不声称与未来特征门控的 FP32 运算逐位一致。

原阈值严格 `float32 sigmoid(z)>0.5`。必须重放全部104份 O3/v1 概率并与父数据逐位一致，
再检查它们的原 mask 与 `z>0` 一致；任一不一致停止，不默默更换原评价口径。
正GT像素可补回 iff upper>0，背景像素可删 iff lower<=0；端点恰0的边界单列。
可修背景仅在 lower=0 时属于闭区间放松，不保证有限 tanh 参数能达到。

oracle 默认 a=1 保留v1，仅对可修的FN/FP选择有利端点0或2。不可修像素保留原预测。
逐像素自由选择使TP最大、FP最小，因此给出该放松空间的像素IoU上界。
oracle依赖训练GT，不是可部署模型，不保存或命名为 best 权重。
组件匹配的Pd/Fa并非像素单调函数：同时报告原协议的固定阈值Pd/Fa及目标状态，
但不把它们称为Pd/Fa上界，不为二值oracle伪造连续评分或有意义的FROC曲线。

## 范围与输出

保持完整 train/test 划分不变。仅复用封存v1中的NUDT原Pilot64前8张×原13条件，
以及同一8张训练GT；不新建验证集、不读test数据、不生成退化、不重新运行O3。
使用原 best_miou 宿主与v1第128步权重；本轮0个optimizer step，不改变任何模型参数。
先校验父366个文件和87个绑定，再建立新manifest绑定配置、说明、代码和测试。

全量输出逐图像素可达性、逐GT目标覆盖/可达覆盖及v1→oracle状态转移、13条件指标，
clean单列、12个非clean等权宏平均、四家族单列；所有计数保留原分母。
GT组件内没有可达正像素仅表示该组件GT像素无法补回，不等于原质心匹配Pd必然为0。
保存两套真实logits、oracle gain/二值mask/可达性数组，及Source/O3/v1/oracle共416张mask。
不覆盖父结果；新结果保存在 `results/cr_sitta/o3_residual_reachability_v3/R0/`。
前后复核父数据和代码哈希；成功封存ledger/COMPLETE，异常保留FAILED，不自动重试。

## 预先固定的解释规则

- 有不可修错误：否定“仅此有界标量机制足以修复全部这些像素错误”，量化剩余比例，
  不因此否定其改善一部分错误的可能。
- 无不可修错误：只是理想表达空间包含正确二值mask；不能推出输入可辨识、可学习或泛化。
- oracle改变组件连接并丢失检测：记录TP→FN，不能把该oracle选择当成整个表达空间的Pd上界。
- 不以oracle的大幅收益当作新方法性能刷新；不据此自动进入全训练或正式test。
- 若表达空间不足，下一步需研究修正方向/判别依据；本诊断不能单独证明应该更换骨干、
  添加注意力、增加通道或引入某个具体论文模块。
